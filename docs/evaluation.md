# 评测口径、结果与局限

## 如何复现

```bash
python eval/generate_fixtures.py
pytest
python eval/run_eval.py eval/results
```

`generate_fixtures.py` 生成 50 个建模用例与 20 个预埋缺陷用例。`run_eval.py` 使用确定性规划器和模拟引擎，输出 golden manifest、逐例 JSON、汇总 Excel/PDF/JSON。重复运行会改变运行 ID 与耗时，不会随机改变构件几何。

故障注入另外验证了：漏掉首面墙一次时第 2 轮通过；连续两次时第 3 轮通过；持续三次时三轮后失败，最终模型为空。这个测试证明回滚与瞬态重试路径可工作，不证明任意语义差异可自动修复。

## 为什么不能把 100% 直接写进简历

- 用例由本项目规划器支持的模板生成，模板与实现同源，存在覆盖偏差。
- 评测后端是共享代码的模拟引擎，golden 由编译器展开得到，主要验证端到端接线和确定性，不等同于独立第三方验收。
- 审图用例针对已实现的 rule_id 预埋，100% 只表示规则回归通过，不能外推到未知图纸或法定规范检出率。
- 没有真实 Revit/AutoCAD/SolidWorks、外部 VLM 或人工盲评。
- 平均耗时是沙箱模拟执行，不是工业软件响应时间。

## 实机指标应如何替换

1. 冻结一组未参与开发调参的指令与缺陷图纸。
2. 独立定义 golden，不直接复用被测编译器输出作为唯一真值。
3. 在工程副本运行，保存原生截图、只读构件清单和回滚证据。
4. 报告样本量、失败案例、置信区间、模型版本、耗时与 Token。
5. 将“模拟引擎结果”和“实机结果”分表，不混用。
